## 插图复现

在专栏根目录执行：

```bash
node 16-配套代码/render_figures.mjs /tmp/llmgw-ch16-preview
```

依赖 Node.js、`sharp`、`@napi-rs/canvas` 和中文字体。默认字体为 Hiragino Sans GB，可通过 `DIAGRAM_FONT` 指定其他已安装字体。模块可从正常 Node 模块路径加载，也可用 `DIAGRAM_NODE_MODULES` 指定已安装依赖目录。更换字体后需重新检查文字宽度和布局。

正式 PNG 写入 `配图`，可编辑 SVG 写入 `配图/源文件`；彩色 / 灰度预览以及文字、节点、连线的几何数据写入指定预览目录。吊销图的竖向生命线是辅助线，与流程连接线分别处理。

## 图示与数字的边界

图 16-1 的组织、团队、应用结构是教学示例，不规定所有产品的实体关系。应用 A 的请求通过已验证凭证关联稳定应用主体，并通过可信上下文关联终端用户；两者不是固定的父子层级。多把 Key 可属于同一应用，换 Key 不自动产生新的应用预算。多层用量用于分别约束，不表示把同一费用重复计入总账。

图 16-2 表示逻辑处理关系，不能用图中距离推算传播耗时，也不承诺各实例同时完成。虚线箭头表示提交确认和已应用版本报告；竖向虚线仅是泳道辅助线。应先可靠保存吊销状态，再传播并观察实际覆盖范围。状态有效性、失联处理和吊销时限需要具体部署兑现；已经执行的调用还需按策略处理取消与最终费用。

图 16-3 的连线表示凭证与配额域的归属，不是先调用再检查额度的执行时序。三个租户的上限各为 5 万 TPM，合计可达 15 万 TPM，大于同一配额域的 10 万 TPM。示例假设同一 Token 计量口径和窗口，不能把它作为生产限流配置。独立容量仍需检查更高层共享限制。

正文预算例子从剩余 1.00 元开始，只展示本例新增实耗：A 预留 0.80 元后，剩余可用 0.20 元；B 也申请 0.80 元，因此不能被接纳。A 最终实耗 0.60 元，释放预留差额后，新增实耗 0.60 元、未结算预留 0.00 元、可用余额 0.40 元。例子假定其他适用预算均足够、估计覆盖费用且没有额外支出，不代表所有真实接口都有可执行的费用上界。

正文团队预算例子中，1000 元与其他应用的 9000 元合计达到团队 1 万元上限；单应用 3000 元的配置不能覆盖团队余额耗尽的事实。
