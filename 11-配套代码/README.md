# 第 11 讲：负载均衡的教学模拟

本实验用于理解**固定并发槽位、长尾请求和容量差异**如何影响分发策略，不是 vLLM、GPU 或真实网关的性能基准。正文和配图使用 `results.json` 的 schema 2 结果。

## 复现

模拟和测试仅需要 Python 3 标准库。在专栏根目录执行：

```bash
python3 -m unittest discover -s 11-配套代码 -v
python3 11-配套代码/lb_sim.py 1800 10 --workers 4
```

默认结果写到脚本同目录的 `results.json`，与调用命令的工作目录无关。可用 `--output /path/to/results.json` 另存。绘图脚本 `plot_results.py` 需要 Matplotlib 和中文字体，读取结果并生成书稿中的 SVG / 300 dpi PNG，不重新运行模拟。

```bash
python3 11-配套代码/plot_results.py
```

绘图使用 Matplotlib 3.11.2 和 Hiragino Sans GB；没有该字体时，可用 `--font` 指定已安装的中文字体。正文插图参考宽度 150 mm、最小字号 9 pt。

## 输入与处理模型

- 到达窗口为 `[0, 1800)` 秒；前 60 秒为预热，仍参与资源竞争。统计对象为到达时间在 `[60, 1800)` 的请求。
- 4 个副本，每个最多同时运行 16 个请求。超出部分进入该副本的 FIFO 队列；网关没有全局等待队列。
- 同构速度系数 `[1, 1, 1, 1]`，到达率 3.3 次/秒；异构系数 `[1, 1, 1, 0.6]`，到达率 2.9 次/秒。到达过程为泊松过程。两场景到达率不同，只在各场景内比较策略，不把跨场景差值全部归因于慢副本。
- 输出长度为 `min(4000, floor(LogNormal(log(200), 1.1)) + 1)`；提示词长度为 `min(16000, floor(LogNormal(log(1000), 0.8)) + 1)`。
- 合成输出估计为 `实际输出长度 × LogNormal(0, 0.6)`。误差倍率中位数为 1，均值大于 1；它不是已训练或评估过的预测器。
- 请求先预填充，再解码。预填充耗时为 `提示词 Token × 0.00015 / 速度系数` 秒，占用槽位；结束时产生首 Token，该 Token 计入输出长度。
- 解码阶段每个运行请求的每 Token 时间为 `(0.02 + 0.0015 × 当前运行请求数) / 速度系数` 秒。连续进度按 0.01 秒时间步近似，输出可在内部按小数 Token 扣减。
- 预填充期间也计入运行请求数，但预填充计算没有共享的算力或批次 Token 预算。模型没有实现 KV Cache、抢占、chunked prefill、PD 分离、网络或网关开销、真实超时和取消。

**本模型的入队条件由固定槽位决定，因此会偏重能够反映槽位占用的指标。**槽位不是实际 GPU 调度的完整模型，结果不能直接迁移到生产系统，也不应据此宣布某一类负载指标普遍最优。

## 策略与可见信息

| 策略 | 选择方式 | 边界 |
| --- | --- | --- |
| `rr` | 等权轮询 | 不观察实时负载 |
| `weighted_rr` | 按速度系数做平滑加权轮询 | 已知静态容量权重，不适应瞬时拥塞 |
| `random` | 等概率随机 | 与容量加权随机不同 |
| `least_req` | 最小的运行数 + 排队数 | 全局即时可见，是理想化计数 |
| `p2c` | 随机取两个副本，选在途较少者 | 使用相同即时计数；同值沿随机抽样顺序选择 |
| `initial_tok` | 未完成请求的初始输出估计之和 / 速度 | 完成时才移除，生成中不递减；取代旧名 `least_tok` |
| `remaining_tok` | 每个请求的 `max(1, 输出估计 − 已生成数量)` 求和 / 速度 | 随进度递减，但预测可能错误；假设能观察生成进度 |
| `remaining_tok_oracle` | 真实剩余输出之和 / 速度 | 使用未来真实长度，仅用于对照，不是可上线策略或理论下界 |
| `least_req_stale` | 最小的计数快照，每 2 秒刷新 | 刷新间不叠加本地派发量，刻意模拟纯旧快照 |
| `p2c_stale` | 两次随机选择，比较同一旧快照 | 随机性缓解集中选择，但不消除信息延迟 |

三种 Token 策略都**只计输出**，不含未处理提示词、缓存复用收益和 KV 占用，也不预测新请求在目标上的完成时间。不能将其称为完整“剩余推理工作量”。除轮询及两次抽样中的顺序外，最低分同值用随机数打破平局。加权轮询权重相同时与普通轮询一致。

## 统计窗口与可比性

1. 每个场景使用种子 1—10。对同一场景、同一种子，先生成同一批请求及估计值；策略随机源独立，不改变请求序列。
2. 1800 秒停止新请求后，继续运行直到**全部已到达请求完成**。默认最多排空 3600 秒，超限直接报错，不用部分样本发布 P99，也不覆盖已有结果。
3. TTFT 为模型内“到达 → 预填充结束产生首 Token”，包含队列等待及预填充；不包含网络、网关或界面展示耗时。
4. 每次运行使用排序后的 `floor(p × (n−1))` 位置求分位数，空样本为 null。图中的点是 10 次运行各自 P99 的中位数，横线是其最小—最大值，**不是置信区间，也不是合并全部请求后的 P99**。
5. 原始逐次结果保存样本数、完成数、停止到达时未产生首 Token 的数量、排空终点、各副本分配量和请求集 SHA-256；元数据保存时长、种子、分布参数、算法源文件 SHA-256 和 Python 版本。相同种子跨策略的请求指纹应完全一致。

## 2026-11-01 修订

旧版到达时限就结束，尚未产生首 Token 的请求不进入分位数，会低估拥塞策略的尾延迟。本版排空全部请求，并增加排空上限失败检查；首 Token 也从剩余输出中扣除，避免多算一个 Token。使用整数时间步索引推进时间及刷新快照，避免浮点累加影响刷新时刻。

旧 `least_tok` 改名为 `initial_tok`，以符合其“初始估计到完成前不递减”的含义；增加剩余输出估计、真实剩余输出对照和容量加权轮询。所有策略重新运行，旧结果不能与本版数字直接拼接比较。

`test_lb_sim.py` 的 7 项测试覆盖截止时尚未响应的请求、排队尾部、预热边界、排空超限、进度扣减、跨策略同样本，以及加权轮询的容量份额。完整运行还应确认 `n == eligible`、`completed == arrived`，并从逐次结果重新计算汇总。
