# 第 18 讲：身份与鉴权

本目录保存三张插图的绘制代码与复现说明。正文中的凭证验证、授权、吊销、代理身份交接、出站轮换与令牌交换是架构说明，没有提供可部署的认证引擎或产品配置。

## 插图复现

在专栏根目录执行：

```bash
node 18-配套代码/render_figures.mjs /tmp/llmgw-ch18-preview
```

依赖 Node.js、`sharp`、`@napi-rs/canvas` 和中文字体。默认字体为 Hiragino Sans GB，可通过 `DIAGRAM_FONT` 指定其他已安装字体。模块可从正常 Node 模块路径加载，也可通过 `DIAGRAM_NODE_MODULES` 指定已安装依赖目录。更换字体后需重新检查文字宽度和布局。

正式 PNG 写入 `配图`，可编辑 SVG 写入 `配图/源文件`；彩色 / 灰度预览及文字、节点、流程连线几何数据写入指定预览目录。绘制过程不调用身份服务、模型服务或其他网络 API。

## 图示的适用边界

图 18-1 是网关托管上游凭证的架构示例。三块面板说明三段职责，并不要求调用方一定使用某种凭证。API Key、访问令牌和证书均需配合实际认证机制；证书认证还需相应的私钥持有证明。工作负载身份可以与 OAuth、JWT、mTLS 等组合，服务身份不会自动证明终端用户。

图 18-2 只描述受保护请求的逻辑处理顺序。API Key、JWT、不透明访问令牌和证书检查项并不完全相同，应按已配置机制执行；不能把图中的受众、签发方等条件不加区别地应用到所有凭证。四条拒绝分支独立绘制，不合并成重叠的竖向连线。具体实现可以缓存或合并步骤，但不能放松对应的验证与授权条件。图片没有规定各错误统一返回何种 HTTP 状态码。

图 18-3 仅展示允许路径：令牌 A 面向网关，网关通过自己的获准客户端认证向授权服务器提出交换请求，服务器按策略签发面向工单服务的令牌 B。“只读工单”是示例中的获准权限，不意味着交换协议自动缩小权限。用户与代理方如何关联，依具体令牌格式与委托约定决定，不要求所有令牌都携带同一种 `act` 声明。工具服务仍需验证令牌及具体工单权限。

图 18-3 的纵向虚线是泳道辅助线，不是请求或授权连接线；横向实线表示请求，横向虚线表示交换结果。消息标签有白色底衬，避免辅助线穿过文字。图中距离不代表网络耗时、令牌寿命或吊销延迟；没有画业务数据返回和全部错误路径。
