# 第 19 讲：护栏的拦截架构

本目录保存三张插图的绘制源码与复现说明。正文中的检查路径、并行前提、分段放行与故障处理是架构说明，没有提供可部署的审核服务或网关插件。

## 插图复现

在专栏根目录执行：

```bash
node 19-配套代码/render_figures.mjs /tmp/llmgw-ch19-preview
```

依赖 Node.js、`sharp`、`@napi-rs/canvas` 和中文字体。默认字体为 Hiragino Sans GB，可以用 `DIAGRAM_FONT` 指定其他已安装字体；更换字体后需要重新检查文字宽度与布局。依赖从正常 Node 模块路径加载，也可用 `DIAGRAM_NODE_MODULES` 指定已有模块目录。

正式 PNG 写入 `配图`，可编辑 SVG 写入 `配图/源文件`；彩色与灰度预览、文字和流程连线的几何数据写入指定的预览目录。绘图不访问审核服务、模型服务或其他网络 API。

| 图号 | 文件名 | 内容与位置 |
| --- | --- | --- |
| 19-1 | `19-护栏执行与并行检查` | 新增于“有条件地并行执行”，区分前置条件、两条并行路径与共同放行条件 |
| 19-2 | `19-流式审查` | 原图在“流式输出的审查”一节原位重绘；三种交付方式与检测技术分开表达 |
| 19-3 | `19-流式缓冲与放行边界` | 新增于“流式内容什么时候可以放行”，呈现 A 已发送、B 等待、C 先返回的状态与后续分支 |

三图参考宽度为 150 mm，最小文字约 9.1 pt；PNG 宽 1772 像素、密度 300 dpi。SVG 保留可编辑文字，不引用外部图片，不放公众号标识。颜色只辅助区分，灰度下可以依靠文字、位置和线条理解内容。分支共用一段干线时只绘制一次，后续箭头分别走线。

## 图示边界

图 19-1 是前置条件满足后的可选并行路径，不是所有请求的默认执行方式。生成模型与远程审核服务都要满足相应的授权和数据处理条件；要求调用前完成的内容检查也属于前置条件。图中按阻断式策略处理未知结果，未展示策略预先允许的故障降级路径。下游工具执行仍需独立获准；上游自主执行工具时应另外约束副作用。取消是尽力而为，不能撤回已出站数据，也不保证上游立即停算。

图 19-2 各面板的时间均向右，仅表达因果先后，不比较真实耗时或吞吐。前两行展示检测允许时的交付时机；第三行展示检测完成前已有内容交付的情形。全量缓冲可以一次返回，也可以分块发送已批准内容。分段检测不意味着每段可以脱离上下文判断。底部的检测技术是另一维度，不是第四种交付策略；使用流式模型不自动保证在交付前拦截风险。

图 19-3 是同一有序输出通道的示例，不要求所有协议、候选和内容通道共用一个全局序号。C 的检查先返回允许，也不能越过 B；B 允许之后，C 仍需满足上下文和其他交付条件。拒绝分支包含按强制策略处理的超时，不能通过刷新缓冲恢复服务。正常结束需要尾段通过必需检查并完成交付。“通过”表示当前策略判断，不意味着检测绝无漏报；后续上下文可能揭示已交付前缀中的风险。

正文的 300 ms 与 100 ms 是教学数字。在前置检查相同、检查与推理不争抢资源且忽略输出审查等开销时，串行约 400 ms，并行约 300 ms。没有将这些数字作为产品基准，也没有声称并行消除了审核延迟。
