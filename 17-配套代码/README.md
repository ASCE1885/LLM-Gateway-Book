# 第 17 讲：Token 计量与成本治理

本目录提供离线的 Token 口径适配、教学计价示例、回归用例和三张配图的可编辑源代码。示例不访问网络、不读取 API Key，也不会产生模型费用。

## 运行示例与检查

在专栏根目录执行，Python 3.9 或更高版本即可，无第三方 Python 依赖：

```bash
python3 -B 17-配套代码/demo.py
python3 -B -m unittest discover -s 17-配套代码 -v
```

正文中的 Python 代码块可在本目录运行。`cost_ledger.py` 保留原文件名，但功能范围是教学用的适配与计价函数，没有实现持久账本。

| 示例 | 正确结果（虚构人民币价格） |
| --- | --- |
| 无独立写入费的 Chat 模型，与等价的 Messages 用量 | 均为 0.066 元 |
| 漏计缓存读取 / 忽略读取折扣 | 错误结果分别为 0.056 / 0.156 元 |
| 500 普通输入、4000 写入（两种 TTL 各半）、300 输出 | 0.082 元；错误合并按 5m 计价为 0.067 元，整次请求少算约 18.3% |
| 只比较上一行的写入部分 | 0.065 元与 0.050 元，少算约 23.1% |
| Responses：12000 输入，4000 读取，7000 写入（30m 为 3000，12h 为 4000），900 输出 | 普通输入 1000，总费用 0.1875 元 |
| 混合 TTL 示例缺少 TTL 明细或写入单价 | 最终金额为 `None`，待确认；已计价部分为 0.017 元 |

所有单价均为虚构示例，不能作为任何真实模型的当前价格配置。15 项回归测试覆盖等价口径、两类写入分桶、推理子集、缺价 / 缺字段 / null、未分类写入、异常计数、部分与估算状态、能力不匹配、原始数据副本、小额金额精度等情况。

## 数据与适配边界

- `Count` 为每项保留 `value`、`source`、`complete`。`None` 表示未知，已知零仍是零；网关估算与观察来源可以单独标注。
- `from_openai` 必须明确 `api`、`cache_writes` 和 `final`。`cache_writes=False` 仅用于已核实没有独立缓存写入计费的模型，不能因为响应缺字段就选择 False。返回的写入量若与该能力配置矛盾会报错。
- 示例解析 Chat Completions 与 Responses 的对应字段。当前只对 Responses 解析已经核实的 30m / 12h TTL 明细；Chat 返回写入量但没有可解析分类时保留未分类，不猜测写入价格。
- `from_anthropic` 按普通输入、缓存读取、缓存写入及 5m / 1h 明细归一化；缺失 TTL 保留未分类余量。完整明细与总量不符、已知子项超过总量等情况会报错。
- 计价项目保存在 `items`，`reasoning` 是分析子集，不重复参与计价。仅缺少推理细分时，若同价输出总量已完整，仍可计算其输出费用。这里不把“非推理部分”命名成可见文本。
- 适配器接收已聚合的 usage 对象，**不负责流式事件聚合**。只有确认传入用量完整时才传 `final=True`；False 会保守地把已提供项目标为部分用量。更细的“输入完整、输出未知”可通过各项 `Count` 表达，测试中有示例。
- 原始 usage 深拷贝到结果中。示例数据对象面向单进程教学使用，不是不可篡改的审计存储。

`PriceCard` 采用每百万 Token 的 `Decimal` 单价。调用者先选好适用价格版本和币种；代码不会根据模型、时间、区域、档位或合同自动匹配价表。金额保留小额精度，`demo.py` 的六位小数仅用于显示，不构成真实厂商舍入规则。

`price_cost` 返回的状态含义如下：

| 状态 | 含义 |
| --- | --- |
| `pending` | 存在未知用量、未分类的非零写入或缺少单价；`total=None`，`known_subtotal` 仅表示已经能够计价的部分 |
| `estimated` | 项目都有数量和单价，但包含部分用量或网关观察 / 估算；`total` 是暂算值 |
| `calculated` | 输入到计算器的计价项目均为完整厂商报告，按指定价表完成计算；并不表示已与厂商结算核对 |

已计价部分可能同时包含估算，需结合 `issues` 与各项来源解释，不能一律当作严格下界。缺少价格不会回退到普通输入价；零数量不会因为缺少单价而产生费用。不同币种的结果不得直接累加。

本例限定同一文本输入价 / 输出价下的 Token 项目。图片、音频、工具调用次数、复杂价格阶梯、汇率、税费、折扣、退款、持久账本、幂等补报、内部分摊与厂商账单对接都需要另外实现。正文和图中的记录版本、补报核对及有效汇总为架构建议，本目录未实现或测试生产账本与分布式预算系统。

## 插图复现

在专栏根目录执行：

```bash
node 17-配套代码/render_figures.mjs /tmp/llmgw-ch17-preview
```

依赖 Node.js、`sharp`、`@napi-rs/canvas` 和中文字体。默认使用 Hiragino Sans GB，可通过 `DIAGRAM_FONT` 指定其他已安装字体。模块可从正常 Node 模块路径加载，也可用 `DIAGRAM_NODE_MODULES` 指定依赖目录。替换字体后需重新检查布局。

正式 PNG 写入 `配图`，可编辑 SVG 写入 `配图/源文件`。彩色 / 灰度预览与文字、节点、连接线几何数据写入指定预览目录。

| 图号 | 文件名 | 用途与位置 |
| --- | --- | --- |
| 17-1 | `17-用量到计费项目` | 新增于口径一节，说明输入的互斥分类、输出的分析子集与缺失信息 |
| 17-2 | `17-请求与调用成本归属` | 新增于归属一节，关联业务请求、模型尝试与辅助调用，保留未知成本 |
| 17-3 | `17-成本治理` | 原图原位重绘，保留在成本治理一节，加入对账和效果评估的反馈关系 |

三图参考宽度 150 mm，最小文字约 9.1 pt；PNG 宽 1772 像素、300 dpi。SVG 保留可编辑文字，无外部图片，不放公众号标识，灰度下通过文字、位置与连线保持可读。

图 17-2 上方连线表示调用与业务请求的归属，A1 → A2 表示 Fallback；下方表示成本归集及补报处理，不表示精确执行时序。金额为虚构示例：0.002 + 0.066 = 0.068 元，A1 金额未知，因此最终总额仍待确认。图中距离不代表耗时，也没有声称收到最终答案后一定能立即获得全部用量。
